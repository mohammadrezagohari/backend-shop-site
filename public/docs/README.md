# مستندات API گلدن اید

Swagger UI: <http://localhost:8000/docs/>

نسخه فعلی ۵۵ عملیات دارد. تنظیمات محیط در `ENVIRONMENTS.md`، محصولات متنوع در `CATALOG.md` و اتصال بازارگاه‌ها در `MARKETPLACES.md` ریشه پروژه توضیح داده شده‌اند. فیلتر `tag` برای محصولات و مقاله‌ها و endpointهای وضعیت/همگام‌سازی مدیریت و خروجی ترب نیز ثبت شده‌اند.

قرارداد قابل دریافت و ورود به ابزارهای API: [openapi.yaml](./openapi.yaml)، با فرمت OpenAPI 3.1.
آدرس پایه `/api/v1` نسبت به سرور میزبان مستندات است.

تمام مسیرهای `routes/api.php` شامل GET، POST، PUT، PATCH و DELETE در ۱۹ گروه ثبت شده‌اند:

- احراز هویت
- دسته‌بندی‌ها، محصولات و دیدگاه‌ها
- مقالات
- سبد خرید
- سفارش‌ها و پرداخت آزمایشی
- مدیریت: داشبورد، محصولات، دسته‌بندی‌ها، سفارش‌ها، کاربران، مقالات و دیدگاه‌ها
- نمادها و گواهی‌ها، مدیریت نمادها و گواهی‌ها

برای آزمودن مسیرهای محافظت‌شده، از پاسخ ورود یا ثبت‌نام `data.token` را بردارید و در Authorize وارد کنید؛ پیشوند Bearer را وارد نکنید. توکن‌ها ۷ روز اعتبار دارند. مسیرهای مدیریت علاوه بر توکن، `is_admin=true` نیاز دارند.

برای حفظ سبد مهمان، مقدار `data.token` پاسخ `GET /cart` را در هدر `X-Cart-Token` درخواست‌های بعدی بفرستید. سفارش از آرایه `items` ساخته می‌شود و سبد را خودکار پاک نمی‌کند.

نمونه‌ها از شناسه‌های فرضی استفاده می‌کنند؛ شناسه محصول، دسته‌بندی و سفارش را با داده موجود جایگزین کنید. پرداخت آزمایشی را با شروع پرداخت و سپس ارسال `payment_token` پاسخ به مسیر verify بررسی کنید.

هنگام تغییر مسیرها، اعتبارسنجی کنترلرها یا مدل پاسخ، فایل OpenAPI را نیز به‌روزرسانی کنید. تفاوت PUT و PATCH منابع مدیریتی در توضیحات عملیات مشخص شده است.

رابط Swagger از CDN دریافت می‌شود و برای بارگذاری اولیه به اینترنت نیاز دارد. فایل YAML مستقل قابل دریافت است.

مرجع تنظیمات رابط: [Swagger UI configuration](https://swagger.io/docs/open-source-tools/swagger-ui/usage/configuration/).
